# Guest brochure generator (RU/EN) — passwords + QR

Сервис хранит Wi‑Fi пароли в собственной базе и генерирует один PDF для двусторонней печати:

- пароли массово вставляются в веб-интерфейс из буфера обмена;
- пользователь указывает количество брошюр RU и EN;
- сервис резервирует нужное количество доступных паролей;
- в PPTX-шаблонах подставляется пароль, а `{{QR_WIFI}}` заменяется QR-кодом;
- после успешной генерации пароли помечаются использованными и больше не выдаются;
- если генерация завершилась ошибкой, зарезервированные пароли возвращаются в список.

Google Sheets и ключ Google service account больше не нужны. На 28 июля 2026 года
997 доступных паролей из вкладки «Пароли» уже перенесены в локальную базу
`data/vouchers.db`; исходная таблица оставлена без изменений.

29 июля 2026 года создан отдельный Supabase-проект
`artstudio-wifi-vouchers` (`vsrletehzqlusmunvqji`, Frankfurt), и все
997 уникальных паролей перенесены в закрытую PostgreSQL-схему
`wifi_voucher`. Контрольная сверка: 997 всего, 997 доступно, 0 в резерве,
0 использовано, 0 дубликатов.

Целевая online-конфигурация: GitHub → Render Docker → Supabase Postgres.
Локальный standalone-режим продолжает работать на SQLite. Подробная схема,
API-контракт и путь интеграции в общую панель описаны в
[`docs/architecture.md`](docs/architecture.md).

## Интерфейс

Откройте главную страницу приложения. На ней можно:

1. Вставить содержимое TXT/CSV или перетащить файл в панель импорта.
2. Проверить предварительный разбор партии: новые значения, дубликаты и строки,
   требующие внимания.
3. Добавить до 5000 значений. Дубликаты внутри файла и уже существующие в базе
   не загружаются.
4. Найти и вручную исправить доступный пароль прямо в таблице.
5. Выделить одну или несколько строк и выполнить «Скопировать и выдать».
   Значения попадут в буфер обмена и атомарно уйдут из доступных в использованные.
6. Указать количество русских и английских брошюр и скачать готовый PDF.

Новые партии от провайдера дальше добавляются через то же поле массовой вставки.

## Хранение данных

По умолчанию локальная база создаётся в `data/vouchers.db`. В Docker без
`DATABASE_URL` используется `/data/vouchers.db`.

Если задан `DATABASE_URL`, приложение использует PostgreSQL. Для Render +
Supabase нужен URL session pooler на порту 5432: Render не поддерживает прямое
IPv6-подключение Supabase Free. Таблицы создаются в закрытой схеме
`wifi_voucher`.

Для production обязательно подключите постоянный volume или каталог. Иначе база
будет потеряна при пересоздании контейнера. В `compose.yaml` каталог `./data`
смонтирован в контейнер как `/data`, поэтому уже мигрированная база используется
без дополнительного импорта.

SQLite подходит для локального режима: импорт, резервирование и завершение выдачи
выполняются транзакционно, поэтому параллельные запросы не получают один пароль.
PostgreSQL online-режима поддерживает конкурентные процессы через
`FOR UPDATE SKIP LOCKED`. Текущий Render Free всё равно запускается одной
репликой.

## Как проходит генерация

1. Интерфейс проверяет, достаточно ли доступных паролей.
2. SQLite-транзакция резервирует самые ранние значения.
3. Для каждого пароля создаётся QR-код и экземпляр PPTX-шаблона.
4. LibreOffice в headless-режиме конвертирует PPTX в PDF.
5. После успешной сборки пароли помечаются использованными.
6. При любой ошибке текущая партия возвращается в доступные.
7. После аварийного перезапуска незавершённые резервы также освобождаются.

## Защита интерфейса

Поскольку интерфейс показывает рабочие Wi‑Fi пароли, для опубликованного приложения задайте:

- `ADMIN_USERNAME` — имя пользователя, по умолчанию `admin`;
- `ADMIN_PASSWORD` — пароль для HTTP Basic; если переменная пуста, авторизация отключена.

Endpoint `/health` остаётся открытым для health-check платформы.

## Переменные окружения

- `DATABASE_PATH` — путь к SQLite-базе, по умолчанию `data/vouchers.db` локально и `/data/vouchers.db` в Docker;
- `DATABASE_URL` — PostgreSQL connection string; при наличии имеет приоритет над SQLite;
- `ENVIRONMENT` — `development` или `production`; в production пустой `ADMIN_PASSWORD` запрещён;
- `HOTEL_ID`, `HOTEL_NAME` — постоянный идентификатор и название отеля;
- `RESERVATION_TTL_MINUTES` — срок lease незавершённой генерации, по умолчанию 15 минут;
- `CORS_ORIGINS` — allowlist будущей внешней панели, пусто для same-origin;
- `ADMIN_USERNAME`, `ADMIN_PASSWORD` — необязательная защита интерфейса;
- `TEMPLATE_RU_PATH`, `TEMPLATE_EN_PATH` — пути к PPTX-шаблонам;
- `SOFFICE_BIN` — бинарник LibreOffice. На Windows стандартная установка
  LibreOffice обнаруживается автоматически, в Linux используется `soffice`.

Переменные Google Sheets (`GOOGLE_SA_JSON_PATH`, `SPREADSHEET_ID`, `SHEET_NAME`, `PASSWORD_COLUMN`) больше не используются.

## Редактирование дизайна

Шаблоны лежат в:

- `api/templates/brochure_ru.pptx`;
- `api/templates/brochure_en.pptx`.

Можно менять всё, кроме маркеров:

- `{{PASSWORD}}` — место для пароля;
- `{{QR_WIFI}}` — блок, который заменяется QR-кодом.

Если переместить `{{QR_WIFI}}`, QR-код будет вставлен в новое место автоматически.

## Локальный запуск

Нужен установленный LibreOffice. На Windows стандартный путь определяется
автоматически.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn api.main:app --reload --port 8080
```

В PowerShell активация окружения выполняется командой:

```powershell
.\.venv\Scripts\Activate.ps1
```

Откройте [http://localhost:8080](http://localhost:8080).

## Docker

Первый запуск:

```powershell
Copy-Item .env.example .env
# Замените ADMIN_PASSWORD в .env на длинный случайный пароль
docker compose up -d --build
docker compose ps
```

После запуска интерфейс доступен на `http://localhost:8080`. Контейнер
автоматически перезапускается после сбоя и имеет health-check `/health`.

Обновление после изменения кода:

```bash
docker compose up -d --build
docker compose logs --tail=100 app
```

Остановка:

```bash
docker compose down
```

`docker compose down` не удаляет `data/vouchers.db`. Не используйте ручное
удаление каталога `data`.

Workflow `.github/workflows/docker-ghcr.yml` собирает и публикует образ в GHCR
после прохождения unit-тестов, Python compile check и JavaScript syntax check.

## Online-пилот: Render + Supabase

Supabase-проект и первичный перенос уже выполнены. Для подключения Render:

1. В Supabase-проекте `artstudio-wifi-vouchers` открыть
   **Connect → Session pooler** и скопировать PostgreSQL URL на порту 5432.
2. Подключить репозиторий как Render Blueprint по `render.yaml`.
3. В форме Render заполнить `DATABASE_URL`, `ADMIN_USERNAME` и длинный
   `ADMIN_PASSWORD`.
4. После деплоя проверить `/health`, `/ready`, вход, импорт-дубликат и тестовый PDF.

Скрипт переноса остаётся в репозитории для повторяемой проверки и аварийного
восстановления. Dry-run:

```powershell
.\.venv\Scripts\python.exe -m scripts.migrate_sqlite_to_postgres
```

Применение к пустой PostgreSQL-базе:

```powershell
$env:DATABASE_URL="<Supabase Session pooler URL>"
.\.venv\Scripts\python.exe -m scripts.migrate_sqlite_to_postgres --apply
Remove-Item Env:DATABASE_URL
```

Скрипт выводит только количества, никогда не печатает сами пароли.

Render Free засыпает после 15 минут без входящих запросов, а Supabase Free может
приостанавливать малоактивный проект. Такая конфигурация подходит для пилота,
но не обещает мгновенный круглосуточный первый отклик.

## Резервное копирование и восстановление

Создать согласованную резервную копию работающей SQLite-базы:

```powershell
.\.venv\Scripts\python.exe scripts\backup_database.py
```

Копия появится в `backups/vouchers-<UTC timestamp>.db` и сразу пройдёт
`PRAGMA integrity_check`. Каталог `backups` исключён из Git, поскольку копии
содержат действующие пароли. Практический режим — ежедневная копия плюс хранение
как минимум семи последних версий на другом защищённом диске.

Восстановление:

1. Выполнить `docker compose down`.
2. Сохранить текущий `data/vouchers.db` отдельно.
3. Проверить выбранную копию командой `PRAGMA integrity_check`.
4. Заменить `data/vouchers.db` проверенной копией.
5. Выполнить `docker compose up -d` и проверить `/health` и счётчики.

## Эксплуатационный чек-лист

- Перед каждой печатью сверить счётчик «Доступно» с тиражом.
- Новую партию вставлять целиком: дубликаты не добавятся повторно.
- После скачивания PDF проверить, что счётчик доступных уменьшился на тираж.
- Ежедневно создавать резервную копию базы.
- После обновления приложения проверять `docker compose ps` и `/health`.
- Не запускать несколько реплик приложения поверх одного SQLite-файла.
